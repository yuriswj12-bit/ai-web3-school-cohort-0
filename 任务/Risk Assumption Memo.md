# Risk / Assumption Memo - Agent Economy Live

## 1. 项目成立的核心前提假设（Assumptions）

| 假设编号 | 假设内容 | 重要程度 | 说明 |
|----------|----------|----------|------|
| A1 | ERC-8004 标准已上线且有可查询的链上数据 | 高 | 项目依赖 ERC-8004 的 Identity、Reputation、Validation 数据来构建信赖度分数和 Agent 历史 |
| A2 | 存在足够数量的 Agent 活动数据（交易、交互）可被展示 | 高 | 如果链上 Agent 数量和活跃度过低，实时活动流和排行榜会显得空洞 |
| A3 | Week 4 内能够实现基础的实时/准实时数据更新 | 中 | 包括索引 + 前端展示的闭环 |
| A4 | Cobo Agentic Wallet（CAW）可以在 Week 4 实现基础集成或有效模拟 | 中 | 预测下注层的资金流需要 CAW 支撑，否则难以满足 Cobo 赛道要求 |
| A5 | 团队能在短时间内完成可演示的 MVP（视觉 + 核心交互） | 高 | Hackathon 时间极度紧张，执行力是关键 |

## 2. 最可能失败的地方（Highest Risk Areas）

| 风险点 | 失败概率 | 影响程度 | 具体描述 |
|--------|----------|----------|----------|
| **数据索引与实时性** | 高 | 高 | ERC-8004 数据量或事件结构可能比预期复杂，导致索引开发耗时过长，无法实现实时/准实时更新 |
| **CAW 集成进度** | 高 | 高 | Cobo Agentic Wallet 的实际集成可能比预期复杂，Week 4 难以完成真实资金流 Demo |
| **真实 Agent 数据不足** | 中 | 高 | 如果链上真实 Agent 活动较少，Demo 会显得空洞，影响评委对「隐形经济跳动」的感知 |
| **时间与范围控制** | 高 | 中 | 功能范围失控（想做太多），导致核心 Demo 流程不完整 |
| **多铎 / 多数据源整合** | 中 | 中 | 如果同时支持多链或多个数据源，会大幅增加开发复杂度 |

## 3. Week 4 Fallback Plan（降级方案）

为了确保 Demo Day 能有一个**可稳定演示、视觉击力强**的原型，我们制定了以下三级降级策略：

** 优先级 1（推荐主方案）**：**Mock + 模拟实时 + 部分真实数据**
- 使用 Mock 数据构建完整的「实时活动流 + 排行榜 + Agent 终身历史」视觉流程
- 关键交互（点击 Agent 查看历史、下注入口）可真实操作
- 部分核心指标使用真实 ERC-8004 数据（历史查询）
- CAW 使用 Sandbox / 测试网模拟资金流（或做清晰的 Mock 资金操作流程）
- **优势**：视觉效果和流程完整性最高，风险最低

** 优先级 2**：**重度 Mock + 强调视觉奇观**
- 全部数据使用预设 + 动画模拟实时更新
- 重点展示「隐形经济正在跳动」的视觉效果（交易流脉动、排行榜实时变化、Agent 卡片展开历史）
- CAW 部分做清晰的流程演示 + 权限边界说明（不强求真实链上交互）
- **适用场景**：真实数据接入或 CAW 集成严重受阻时

** 优先级 3**：**最小可运行 Demo**
- 只保留最核心的 2-3 个页面（首页大屏 + Agent 详情页 + 简单下注入口）
- 所有数据 Mock
- 重点讲清楚项目愿景 + CAW 在资金流中的关键作用 + 风险边界设计
- **适用场景**：时间极度紧张时保底方案

** 风险边界记录方式**：
- 所有 Fallback 方案均在文档中明确记录
- Demo 时会说明当前使用的是哪一级方案，以及真实数据/CAW 接入的计划和障碍
