# 深度研究包 - Agent Economy Live

## 1. ERC-8004（Agent Identity & Reputation Standard）

**解决的问题**：
Agent Economy 缺乏统一的身份标识、声誉记录和验证机制。当前链上 Agent 行为分散、不可验证，导致人类和其他 Agent 难以判断「谁可信、谁值得交互」。

**核心机制与边界**：
ERC-8004 通过三个 Registry（Identity Registry、Reputation Registry、Validation Registry）为 Agent 提供链上身份锚定、声誉累积和行为验证。它允许 Agent 注册身份、记录交互反馈，并通过验证者（Validator）机制增加可信度。

**当前边界与缺失**：
- 目前仍处于早期阶段，采用率低，缺少大规模真实反馈数据。
- 声誉计算逻辑和防女巫攻击机制尚未完全成熟。
- 缺少与前端可视化工具的成熟集成方案。

**对我们项目的价值与机会**：
这是我们项目的**核心信任层**。我们将直接读取 ERC-8004 数据构建 Agent 信赖度分数和「一生历史」时间轴，这是现有仪表盘无法做到的差异化点。

## 2. The Graph Protocol（链上数据索引标准）

**解决的问题**：
直接从 RPC 查询链上事件效率极低，特别是在需要实时聚合大量 Agent 交易、声誉变化时，无法支撑高频前端更新。

**核心机制与边界**：
The Graph 通过 Subgraph 将链上事件结构化存储，并提供 GraphQL 查询接口，支持复杂过滤、聚合和实时订阅。它已成为以太坊生态事实上的链上数据查询标准。

**当前边界与缺失**：
- 传统 Subgraph 部署和同步速度较慢，实时性对高频交易流不够理想。
- 多链支持仍需分别部署 Subgraph，维护成本较高。
- 对复杂 Agent 行为模式（多跳交互、声誉加权）的自定义聚合支持有限。

**对我们项目的价值与机会**：
我们需要一个高效的索引层来支撑「实时活动流 + 排行榜」。The Graph 是成熟方案，但我们也在评估更轻量的 Ponder 作为补充或替代，以实现更快的数据新鲜度。

---

## 3. Ponder（现代链上索引框架）

**解决的问题**：
传统 The Graph Subgraph 开发和部署门槛较高，实时性和自定义逻辑灵活性不足，特别是在 Hackathon 快速迭代阶段。

**核心机制与边界**：
Ponder 是一个 TypeScript 原生、轻量级的链上索引框架，支持直接编写索引逻辑、热重载、快速部署，并原生支持 PostgreSQL + GraphQL。它特别适合需要强自定义聚合和快速迭代的项目。

**当前边界与缺失**：
- 生态成熟度不如 The Graph，社区示例和工具链较少。
- 大规模生产环境下的稳定性和水平扩展能力尚未被广泛验证。
- 缺少原生的多链统一管理方案。

**对我们项目的价值与机会**：
Ponder 非常适合我们 Week 4 MVP 阶段使用，能快速实现 ERC-8004 事件监听 + 自定义指标计算（交易量、活跃度、信赖度）。我们计划在 MVP 使用 Ponder 做核心索引，后续再评估迁移到 The Graph 以获得更好生态支持。
